# 🌍 星球綠化造物主（V1.2）

**小學六年級｜圓周長 × 圓面積 × 圓環面積｜多人合作星球養成遊戲**

由一位老師擔任房主，最多五名學生共同建造同一顆星球。學生以圓形相關計算換取森林、衛星、地形修復與能源工程；過程會發生隨機宇宙事件，房主可即時控制節奏。

> 這是**可以實際執行的第一版（MVP）**，不是只有介面設計稿。使用 Node.js 內建 HTTP + Server-Sent Events（SSE）同步，不需要下載任何第三方套件，適合以單一 Render Web Service 部署。

## 目前功能

- **1～5 位學生＋1 位房主**：房間代碼 6 碼；四人不必補齊第五人。玩家可同時作答、所有人看到同一顆星球。
- **動態建造目標**：依開始時學生數與房主設定的局數長度設定，平均每人有相同工作量，並需完成各模式的生態條件：

  | 學生人數 | 15 分鐘 | 25 分鐘 | 40 分鐘 |
  |---|---:|---:|---:|
  | 1 | 4 | 5 | 8 |
  | 2 | 6 | 10 | 16 |
  | 3 | 9 | 15 | 24 |
  | 4 | 12 | 20 | 32 |
  | 5 | 15 | 25 | 40 |

  **通關另需四種工程都至少完成一次、能源站數量與能源存量達標，以及模式指定的生態／防禦條件。** 建議先用 15 分鐘測試，再換正式 40 分鐘局。開局時先固定該局門檻；晚加入的玩家可幫忙，但不會突然提高目標。若有人正式離房，或老師移除離線學生，系統會按剩餘人數下調目標；短暫網路斷線不會改變門檻。
- **三種遊戲模式**：🌱 生命復育（森林、氧氣、水、能源達標）；⚖️ 生態平衡（氧氣、水、能源、穩定度均達標）；🛡️ 危機守護（成功處理一定數量事件，維持穩定度及能源）。開局前由房主選擇，開局後鎖定。生態進度以「建造＋生態條件」加權顯示，未通關不會達 100%。
- **四種數學工程、每類 10 種題型（共 40 種）**：
  1. 🌳 森林：已知半徑或直徑求面積、已知面積反求半徑、森林擴建、面積比較
  2. 🛰️ 星環：已知半徑／直徑求圓周長、地表上方軌道、多圈巡航、反求半徑
  3. 🛠️ 修復：同心圓環、已知內外直徑、半環、雙坑、反推內圈半徑等十種題型
  4. ⚡ 能源：太陽能場圓面積、輸電圓周長、由面積反推半徑、環狀採集面積、雙座電站等十種題型
- **公式＋數值＋單位三重判定**：不只輸入數字；使用 π = 3.14，反求半徑明確列為「圓面積 ÷ π = 半徑 × 半徑」，另可由圓周長反求半徑；優先採用整數與一位小數的結果、避免同一玩家連續出相同題型、接受合理小數誤差。答對提供步驟；答錯會依公式、單位、數值與題型給出概念性診斷（不直接洩漏正確答案）。學生可要求提示。
- **開局 0% 與能源門檻**：沒有任何建築時開發進度固定為 0%；森林、衛星、修復設施、能源站會同步出現在共同星球。側欄提供能源存量條與能源建設進度條，所有模式均需完成能源設施數量與最低能源存量。
- **星球待機動畫與生命指數**：無事件時仍有星球漂浮、地表緩慢移動、星光閃爍；生命指數上升後逐步出現綠地、海洋光影、雲層與生命光點。支援減少動態效果的系統偏好。
- **四種有動畫的事件**：☄️ 隕石墜落、☀️ 太陽風暴、🌧️ 星際生命之雨、🛸 外星探測船。每種事件各有 5 種輪替題型，同類事件再觸發不重複上一題型，並有前情說明、提示及資源獎懲。事件一發生即改變星球資源並有對應視覺異常；全隊只要有一人答對就能解除。失敗後異常會持續削減資源，必須完成對應的森林／星環／地形／能源工程來修復；不摧毀建築以避免少人局崩盤。
- **學生私有手寫計算紙**：建造題和宇宙事件題可開啟計算紙，上方固定顯示原題，滑鼠／手指／觸控筆書寫，具有畫筆、橡皮擦與清空功能。內容不會傳到伺服器，換題會清空。
- **教師即時題目與安全解答**：教師可即時看到所有學生「目前」的題目，但答案、公式與步驟預設隱藏。教師點「顯示答案」才會由伺服器針對該教師個別回傳；學生無此 API 權限。分享畫面前應先按「隱藏答案」。宇宙事件答案也同樣採按鈕顯示。
- **房主工具**：開始／暫停／恢復／結束／重開、題目難度、15／25／40 分鐘、開關自動事件、手動觸發或略過事件、學生作答統計及 CSV 下載。
- **斷線重連與正式退出**：單一瀏覽器會保存臨時進房憑證；只要伺服器仍在運作，可重新整理頁面接回原位置。學生按「離開房間」則釋出席位，重新加入時建立新學習統計。
- **RWD**：桌面、平板、手機皆可使用；純 HTML/CSS/JS 前端，不需建置工具。

### V1.1.0 — 2026-11-10

- **原因 1：題目重複、數字太零碎**：三種工程各增加到五種題型（共十五種），優先使用整數或一位小數結果，避免同一玩家連續抽到相同題型。影響：`server/tasks-v2.js`、`server/game.js`、`client/app.js`。
- **原因 2：反求半徑公式不明確**：新增「圓面積 ÷ π = 半徑 × 半徑」及「圓周長 ÷ (2 × π) = 半徑」兩種公式選項，讓反求題型能實際抽到。影響：`server/game.js`、`server/tasks-v2.js`、`client/app.js`。
- **原因 3：教師無法知道學生正在算什麼**：新增學生即時題目清單；答案與解題過程預設隱藏，須由房主個別按鈕請求，學生不得呼叫解答 API。影響：`server/index.js`、`server/game.js`、`client/app.js`、`client/style.css`。
- **原因 4：星球太快進入生命時代**：新增生命復育、生態平衡、危機守護三種模式；15／25／40 分鐘由每人 3／5／8 項工程計算（至少 4 項），通關需達成模式生態條件。影響：`server/modes-v2.js`、`server/game.js`、`client/app.js`。
- **原因 5：宇宙事件沒影響**：發生當下即修改資源及星球視覺；失敗留下持續異常、產生每次建造額外損耗，並需指定建造類型修復；成功解除則恢復部分資源。影響：`server/game.js`、`server/modes-v2.js`、`server/index.js`、`client/app.js`、`client/style.css`。
- **測試**：`npm test`，14 項自動測試通過（題型、數學、權限、四人平衡、事件、同步）。
- **部署狀態**：本機完成修改及測試；GitHub 提交與 Render 部署狀態以實際後續檢查為準。

## 1. 本機啟動

需安裝 **Node.js 20 或以上**。

```bash
npm start
```

啟動後打開 <http://localhost:3000>。

開發模式可用：

```bash
npm run dev
```

自動測試：

```bash
npm test
```

所有相依套件均為 Node.js 內建模組，**不需 `npm install` 也能執行**。

### 實際試玩步驟

1. 在瀏覽器 A 輸入「數學老師」→「建立我的星球房間」。
2. 在瀏覽器 B（或不同無痕視窗／手機）點「我是學生」，輸入暱稱與六碼房間代碼。
3. 可只邀請四人，甚至一人。房主先把時間調成 **15 分鐘**，降低通關門檻，按「開始任務」。
4. 學生任選四種建造工程，選擇公式、輸入數值、選單位，再按「確認建造」。
5. 房主按「☄️ 隕石」等按鈕試看事件動畫與輪替題目；也可等待自動事件。
6. 題目解答正確，星球上會長出建築，其他學生頁面同步顯示。最後檢查作答統計，匯出 CSV。

## 2. 將檔案放到 GitHub

GitHub 建立一個新 repository，例如 `planet-green-creator`；將這個專案的檔案**整個上傳到倉庫根目錄**（不能只上傳 ZIP，ZIP 應先解壓縮）。若使用 Git，則在專案資料夾執行：

```bash
git init
git add .
git commit -m "Initial Planet Green Creator MVP"
git branch -M main
git remote add origin https://github.com/<YOUR-ACCOUNT>/planet-green-creator.git
git push -u origin main
```

將 `<YOUR-ACCOUNT>` 換成實際 GitHub 使用者名稱，並先在 GitHub 建立對應空白倉庫。

## 3. 部署 Render

1. 打開 [Render Dashboard](https://dashboard.render.com/)，點 **New → Web Service**。
2. 選擇這個 GitHub repository，branch 用 `main`。
3. 設定：
   - **Runtime / Language**：Node
   - **Build Command**：`npm install`
   - **Start Command**：`npm start`
   - **Root Directory**：留空（專案根目錄）
   - **Instance**：可先選 Free
   - **Region**：Singapore（靠近台灣，可用時）
4. 點 **Create Web Service**。Render 會提供 `https://<service-name>.onrender.com` 網址。
5. 若使用 Repo 內附的 `render.yaml`，也可以從 Render 的 **Blueprint** 流程部署。
6. 啟動後可開啟 `https://<service-name>.onrender.com/api/health`，應回覆 `{ "ok": true, ... }`。

伺服器使用 Render 提供的 `PORT`，也綁定 `0.0.0.0`，不必另外設定跨網域或 CDN。

### ⚠️ 第一版限制（上課前務必閱讀）

- **暫存不等於跨週存檔**：房間、建築與統計目前只存在 Node.js 伺服器的記憶體。Render 休眠、重啟、重新部署都可能使本局進度消失；請在課程結束前匯出 CSV。第二版才建議接 PostgreSQL 做真正的跨週養成。
- **Render Free 會休眠**：免費 Web Service 閒置後可能休眠，首次連線可能需要重新啟動。正式上課前請先打開網頁，確認服務已醒來。避免在課中部署新版本。
- **單一伺服器模式**：目前 SSE 同步與房間資料放在單一實例中；若未來要多實例橫向擴充，須改用共用資料庫／訊息佇列。
- **上課版安全性**：學生只用暱稱，沒有帳號與密碼；請不要在暱稱輸入真實敏感資料。房主權限使用每房隨機 token，避免外流。這不是正式帳號系統。
- **題庫仍是第一版**：有三種難度和隨機數值，但尚未包含完整跨週成就、每人獨立角色技能與永久科技樹。
